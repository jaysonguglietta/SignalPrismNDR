# Configuration

SignalPrism NDR is configured with environment variables. Start with `.env.example` for local or container deployments.

## Server

| Variable | Default | Purpose |
| --- | --- | --- |
| `PORT` | `4173` | HTTP port. |
| `HOST` | `127.0.0.1` without auth, `0.0.0.0` with auth | HTTP bind address. |
| `NDR_DATA_DIR` | `.ndr-data` | Local backend data directory. |
| `NDR_API_KEY` | empty | Enables API-key auth when set. |
| `NDR_ALLOW_LOCAL_DEV_ADMIN` | `false` | Allows unauthenticated local-dev admin from non-loopback requests. Use only in trusted development networks. |
| `NDR_ALLOW_DIRECT_INGEST` | `false` | Allows arbitrary S3/CloudWatch ingest payloads instead of requiring managed tenant sources. Use only in trusted single-tenant development. |
| `NDR_PRODUCTION_HARDENING` | `false` | Enables fail-closed startup checks for auth, HTTPS cookies, OIDC transport, and dedicated secrets. |
| `NDR_SESSION_SECRET` | API key/client secret/runtime random | HMAC secret for opaque session IDs. Production requires a dedicated 32+ character value. |
| `NDR_SESSION_TTL_SECONDS` | `28800` | Maximum server-side session lifetime. |
| `NDR_SESSION_COOKIE_SECURE` | `false` | Adds the `Secure` cookie flag. Set `true` behind HTTPS. Terraform enables it when an ACM certificate is configured. |
| `NDR_SESSION_REGISTRY_REQUIRED` | `true` | Requires tenant-stored session presence for revocation and role/status changes. |
| `NDR_EVIDENCE_ATTESTATION_SECRET` | session secret fallback | HMAC key for server evidence attestation. Production requires a separate 32+ character value. |
| `NDR_EVIDENCE_ATTESTATION_KEY_ID` | `signalprism-evidence-v1` | Non-secret attestation key identifier. |
| `NDR_MAX_BODY_BYTES` | `1048576` | Maximum JSON request body. |
| `NDR_MAX_AWS_RESPONSE_BYTES` | `10485760` | Maximum bytes accepted from one AWS API/object response. |
| `NDR_MAX_INGEST_TEXT_BYTES` | `5242880` | Maximum aggregate imported flow-log text per ingest request. |
| `NDR_AWS_REQUEST_TIMEOUT_MS` | `15000` | Signed AWS request timeout. |
| `NDR_OIDC_REQUEST_TIMEOUT_MS` | `10000` | OIDC discovery, token, and JWKS timeout. |
| `NDR_RATE_LIMIT_WINDOW_MS` | `60000` | Rate-limit window. |
| `NDR_RATE_LIMIT_MAX` | `120` | Requests per remote address and authenticated principal per window. |
| `NDR_RATE_LIMIT_MAX_IDENTITIES` | `10000` | Maximum rate-limit buckets retained per task. |
| `NDR_DISTRIBUTED_RATE_LIMIT` | `false` | Uses atomic DynamoDB window counters when `NDR_STORE=dynamodb`; Terraform enables this for shared deployments. |
| `NDR_TRUST_PROXY` | `false` | Trusts the first forwarded client address. Enable only behind a trusted proxy that overwrites the header. |
| `NDR_RETAIN_RUNS` | `50` | Local/DynamoDB run history limit returned by API. |
| `NDR_MAX_JOBS_PER_TENANT` | `50` | Scheduled job quota per tenant. |
| `NDR_MAX_ACTIVE_RUNS_PER_TENANT` | `3` | Concurrent asynchronous import quota per tenant. |
| `NDR_ACTIVE_RUN_SLOT_TTL_SECONDS` | `3600` | Conditional run-slot recovery TTL after process failure. |
| `NDR_MIN_JOB_INTERVAL_MINUTES` | `5` | Minimum schedule interval. |
| `NDR_MAX_JOB_INTERVAL_MINUTES` | `10080` | Maximum schedule interval. |
| `NDR_EXPORT_APPROVAL_TTL_SECONDS` | `900` | Approved export consumption window. |
| `NDR_MAX_PENDING_EXPORT_APPROVALS` | `100` | Maximum unexpired pending export requests per tenant. |
| `NDR_REQUIRE_SEPARATE_APPROVER` | `true` | Prohibits export requester/rule author self-approval. |
| `NDR_STEP_UP_REQUIRED` | `false` | Requires recent OIDC MFA for packet access, controlled export approval, and response approval. Production hardening forces this on. |
| `NDR_STEP_UP_MAX_AGE_SECONDS` | `900` | Maximum age of the OIDC `auth_time` accepted for a privileged approval. |
| `NDR_AUDIT_RETENTION_DAYS` | `2555` | Retention metadata stamped onto audit records. |

When no API key or OIDC issuer is configured, admin APIs are allowed only from loopback requests unless `NDR_ALLOW_LOCAL_DEV_ADMIN=true`. Browser API-key and OIDC login create opaque HMAC-protected HttpOnly SameSite session IDs; principal, CSRF, expiration, and revocation state remain server-side. Mutating session requests include a CSRF header generated by the backend.

## Audit Object Storage

Audit records are always written to the configured metadata store. For immutable production retention, also configure an S3 bucket with Object Lock enabled.

| Variable | Default | Purpose |
| --- | --- | --- |
| `NDR_AUDIT_BUCKET` | empty | Optional S3 bucket for immutable audit-object writes. |
| `NDR_AUDIT_PREFIX` | `signalprism/audit` | S3 prefix for audit objects. |
| `NDR_AUDIT_REGION` | AWS region env or DynamoDB region | Region used for audit object writes. |
| `NDR_AUDIT_OBJECT_LOCK_MODE` | `COMPLIANCE` | Object Lock mode for audit objects. |
| `NDR_AUDIT_OBJECT_STORAGE_REQUIRED` | `false` | When `true`, requests fail if the immutable audit write fails. Terraform sets this to `true`. |

## Evidence Package Storage

The tenant evidence metadata store keeps summaries and bounded samples. Full raw evidence packages are stored separately so large uploads and imports can move to object storage without changing the evidence-run API shape.

| Variable | Default | Purpose |
| --- | --- | --- |
| `NDR_EVIDENCE_BUCKET` | empty | Optional S3 bucket for full raw evidence packages. Empty uses local package files under `NDR_DATA_DIR`. |
| `NDR_EVIDENCE_PREFIX` | `signalprism/evidence-packages` | S3 key prefix or local package namespace. |
| `NDR_EVIDENCE_REGION` | AWS region env or DynamoDB region | Region used for S3 package writes. |
| `NDR_EVIDENCE_RETENTION_DAYS` | `90` | Retention period stamped on evidence packages. |
| `NDR_EVIDENCE_OBJECT_LOCK_MODE` | `GOVERNANCE` | S3 Object Lock mode for evidence package writes. Use `COMPLIANCE` only when policy requires immutable legal retention. |
| `NDR_EVIDENCE_STAGING_BUCKET` | empty | Separate S3 quarantine bucket for direct uploads. Required with production evidence uploads. |
| `NDR_EVIDENCE_SCAN_REQUIRED` | `false` | Holds completed uploads in quarantine until an independent `evidence:scan` attestation. Required in production when evidence storage is enabled. |
| `NDR_EVIDENCE_STORAGE_REQUIRED` | `false` | Fails ingest and analysis when the raw package cannot be retained. Production hardening forces this on. |
| `NDR_EVIDENCE_CHECKSUM_REQUIRED` | `false` | Requires an S3 SHA-256 checksum and immutable object version. Production hardening forces this on. |
| `NDR_EVIDENCE_SCAN_ATTESTATION_REQUIRED` | `false` | Requires a fresh signed scan attestation rather than an unsigned administrative assertion. Production hardening forces this on. |
| `NDR_EVIDENCE_SCANNER_SUBJECTS` | empty | Comma-separated service-account/OIDC subjects authorized to sign scan results. Non-empty in production. |
| `NDR_MAX_EVIDENCE_UPLOAD_BYTES` | 1 GiB | Maximum declared size for one direct upload. |
| `NDR_MAX_ACTIVE_EVIDENCE_UPLOADS` | `20` | Maximum pending/quarantined/scanning sessions per tenant. |
| `NDR_MAX_TENANT_EVIDENCE_RESERVED_BYTES` | 20 GiB | Maximum bytes reserved by active tenant upload sessions. |
| `NDR_DIRECT_UPLOAD_TTL_SECONDS` | `900` | Presigned upload lifetime, bounded to 60-3,600 seconds. |
| `NDR_PACKET_ALLOWED_BUCKETS` | evidence bucket | Comma-separated packet evidence bucket allowlist. |
| `NDR_PACKET_ALLOWED_PREFIXES` | evidence prefix | Comma-separated packet evidence key-prefix allowlist. |
| `NDR_PACKET_OBJECT_VERIFICATION_REQUIRED` | `false` | Requires version, size, checksum, and trusted upload/sensor provenance. Production hardening forces this on. |

When `NDR_EVIDENCE_BUCKET` is set, the bucket must have S3 Object Lock enabled before objects are written. The backend writes package JSON with `x-amz-object-lock-mode` and `x-amz-object-lock-retain-until-date` headers. Production direct uploads first land in a versioned `NDR_EVIDENCE_STAGING_BUCKET`, require a server-observed SHA-256 checksum, and accept only fresh HMAC-signed scanner attestations bound to the exact tenant/object/version. The vault copy is version-pinned and reverified before the staging version is deleted.

## Persistence

| Variable | Default | Purpose |
| --- | --- | --- |
| `NDR_STORE` | `local` | `local` or `dynamodb`. |
| `NDR_DDB_TABLE` | empty | DynamoDB table name when using `dynamodb`. |
| `NDR_DDB_REGION` | AWS region env or `us-east-1` | DynamoDB region. |
| `NDR_DDB_GSI_MIGRATION_MODE` | `dual-read` | `dual-read`, `gsi-only`, or `legacy-only`; keep `dual-read` until schema-v2 backfill and completeness verification finish. |

Local mode stores:

- `jobs.json`
- `ingest-runs.json`
- `workspaces.json`
- `cases.json`
- `evidence-runs.json`
- `evidence-packages/<tenant>/*.json`
- `sources.json`
- `job-runs.json`
- `tenant-users.json`
- `detection-rules.json`
- `enterprise-settings.json`
- `enterprise-artifacts.json`
- `export-approvals.json`
- `telemetry-events.json`
- `correlations.json`
- `response-actions.json`
- `content-bundles.json`
- `sessions.json`
- `audit-<tenant>.ndjson`

DynamoDB mode uses:

- Partition key: `pk`
- Sort key: `sk`
- Record payload: JSON string in `payload`
- Global scheduler index: `kind-createdAt-index` over `gsi1pk`/`gsi1sk` for jobs only.
- Tenant list index: `tenant-kind-createdAt-index` over `gsi2pk`/`gsi2sk` for bounded, newest-first tenant object reads.
- TTL attribute: `ttl` for sessions, leases, and active-run slots.
- Schema marker: `schemaVersion=2`, with top-level `updatedAt` and `revision` values for migration and conditional writes.
- Tenant partitions include workspaces, cases, evidence, sources, job/job-run/run, users, rules, settings, artifacts, approvals, sessions, audit, leases, and run slots.
- Enterprise partitions also include normalized telemetry, correlation findings, response actions, and signed content metadata.

## Durable Ingest Workers

| Variable | Default | Purpose |
| --- | --- | --- |
| `NDR_PROCESS_ROLE` | `all` | `api`, `worker`, or `all`. Terraform runs separate API and worker services. |
| `NDR_QUEUE_URL` | empty | Trusted SQS queue URL for durable managed-source imports. |
| `NDR_QUEUE_ARN` | empty | Queue ARN used as the EventBridge Scheduler target. |
| `NDR_QUEUE_REGION` | AWS/DynamoDB region | Region that must match the queue URL. |
| `NDR_QUEUE_POLL_SECONDS` | `10` | SQS long-poll duration, bounded to 1-20 seconds. |
| `NDR_QUEUE_VISIBILITY_SECONDS` | `900` | Worker visibility timeout, bounded to 30-43,200 seconds. |
| `NDR_REQUIRE_DURABLE_QUEUE` | `false` | Reject startup or async ingest when a queue is absent. Production hardening requires a queue. |
| `NDR_SCHEDULER_MODE` | `local` | `local` timers for development or `eventbridge` for durable production schedules. Production hardening requires `eventbridge`. |
| `NDR_SCHEDULER_ROLE_ARN` | empty | IAM role EventBridge Scheduler assumes to send fixed job messages to SQS. |

Local `all` mode uses a process-local async fallback when no queue is configured. Shared deployments must use SQS so imports survive API replacement and can retry into the DLQ.

## Governed Response And Detection Content

| Variable | Default | Purpose |
| --- | --- | --- |
| `NDR_RESPONSE_EVENT_BUS` | empty | EventBridge bus name or ARN that receives independently approved response actions. |
| `NDR_RESPONSE_EXECUTION_ENABLED` | `false` | Emit approved actions. When false, approvals are retained without execution. |
| `NDR_DETECTION_CONTENT_PUBLIC_KEY_B64` | empty | Base64-encoded trusted Ed25519 public key in PEM or SPKI DER form. |

The application never accepts an arbitrary response webhook. EventBridge targets are provisioned and governed outside the analyst request. Detection private keys remain offline or in a dedicated signing system; only the public verification key belongs in runtime configuration.

## AWS Credentials

Local AWS calls use:

| Variable | Purpose |
| --- | --- |
| `AWS_ACCESS_KEY_ID` | Local access key. |
| `AWS_SECRET_ACCESS_KEY` | Local secret key. |
| `AWS_SESSION_TOKEN` | Optional temporary session token. |
| `AWS_REGION` / `AWS_DEFAULT_REGION` | Default AWS region fallback. |

ECS/Fargate deployments should use task roles. The backend supports ECS container credentials through the standard credential endpoint variables.

AWS calls accept only the commercial and GovCloud regions in the server's static endpoint allowlist. S3 uses the fixed `s3.<region>.amazonaws.com` endpoint with the validated bucket in the encoded path, so tenant-selected bucket names never control outbound DNS. Add newly launched regions through a reviewed code change before using them.

## OIDC/SSO

| Variable | Default | Purpose |
| --- | --- | --- |
| `NDR_OIDC_ISSUER` | empty | OIDC issuer URL. |
| `NDR_OIDC_AUDIENCE` | client ID fallback | Expected token audience. Required when OIDC is enabled unless `NDR_OIDC_CLIENT_ID` is the intended audience. |
| `NDR_OIDC_JWKS_URI` | discovered | Optional JWKS override. |
| `NDR_OIDC_CLIENT_ID` | empty | Browser-safe OIDC client ID. |
| `NDR_OIDC_CLIENT_SECRET` | empty | Optional confidential client secret, backend only. |
| `NDR_OIDC_REDIRECT_URI` | empty/local example | Registered redirect URI. |
| `NDR_OIDC_SCOPES` | `openid profile email groups` | Login scopes. |
| `NDR_REQUIRE_OIDC_TENANT_CLAIM` | `true` | Reject OIDC tokens that do not contain `NDR_TENANT_CLAIM` or an accepted tenant fallback claim. |
| `NDR_OIDC_CLOCK_SKEW_SECONDS` | `60` | Allowed clock skew for issued-at, expiration, and not-before checks. |
| `NDR_OIDC_TOKEN_USE` | empty | Optional provider-specific expected `token_use`/type. |
| `NDR_ADMIN_GROUP` | `ndr-admin` | IdP group mapped to `admin`. |
| `NDR_ANALYST_GROUP` | `ndr-analyst` | IdP group mapped to `analyst`. |
| `NDR_VIEWER_GROUP` | `ndr-viewer` | IdP group mapped to `viewer`. |
| `NDR_DEFAULT_TENANT` | `default` | Tenant used for API-key and local-dev sessions. |
| `NDR_TENANT_CLAIM` | `tenant_id` | OIDC claim used to resolve tenant ownership. |

Tokens must be RS256 signed. The backend checks issuer, audience/authorized party, subject, issued-at, expiry, not-before, tenant claim, redirect URI, and JWKS signature.

`NDR_TEST_AUTH_ENABLED` exists only for loopback integration tests. It is rejected in `NODE_ENV=production` and whenever the server binds beyond loopback.

RBAC is enforced server-side:

- `admin`: full tenant access, tenant user/source ownership management, response approval, signed-content import, source/case/job deletes, enterprise settings, and audit export.
- `analyst`: save workspaces, cases, sources, evidence runs, telemetry and correlations, request response actions, verify signed content, run/schedule ingest, export investigations, and invoke Bedrock.
- `viewer`: read tenant workspaces, cases, sources, evidence runs, telemetry, correlations, response history, jobs, runs, enterprise settings, detection rules, content bundles, and enterprise artifacts.

## Local Examples

API-key mode:

```bash
NDR_API_KEY=dev-key npm start
```

Managed-source ingest:

```bash
NDR_API_KEY=dev-key npm start
```

Create S3 or CloudWatch managed sources in the app, then use source inventory actions for direct or scheduled imports. Arbitrary `/api/ingest/*` payloads require `NDR_ALLOW_DIRECT_INGEST=true`.

Cloud ingest:

```bash
AWS_ACCESS_KEY_ID=... \
AWS_SECRET_ACCESS_KEY=... \
AWS_SESSION_TOKEN=... \
npm start
```

Bedrock:

```bash
NDR_BEDROCK_ENABLED=true \
NDR_BEDROCK_REGION=us-east-1 \
AWS_ACCESS_KEY_ID=... \
AWS_SECRET_ACCESS_KEY=... \
npm start
```

DynamoDB:

```bash
NDR_STORE=dynamodb \
NDR_DDB_TABLE=signalprism-dev \
NDR_DDB_REGION=us-east-1 \
AWS_ACCESS_KEY_ID=... \
AWS_SECRET_ACCESS_KEY=... \
npm start
```
