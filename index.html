Understand NDR and SignalPrism

Learn what network detection and response observes, how SignalPrism turns telemetry into evidence, and how to move from a signal to a defensible decision.

The NDR lifecycle

From network activity to response

Metadata-first, evidence-grounded
1 Observe

Collect VPC Flow Logs, protocol metadata, cloud identity events, and sensor health without relying on endpoint agents.

2 Detect

Compare behavior with rules, peer baselines, threat intelligence, and attack context to find meaningful deviations.

3 Investigate

Correlate entities, communication paths, timestamps, identities, assets, and supporting records into an attack story.

4 Respond

Create a case, preserve evidence, seek approval, contain the threat, verify the result, and retain an audit trail.

Start here

What NDR can tell you

NDR analyzes who communicated, where, when, how, and how that behavior changed. It is strongest at exposing lateral movement, command-and-control traffic, scanning, unusual services, policy violations, and activity that crosses cloud or endpoint boundaries.

Important boundary Flow logs describe connections, not packet payloads. A flow can prove that two entities communicated, but encrypted content usually requires protocol metadata, packet evidence, endpoint context, or another corroborating source.

Decision support

Severity is not urgency

Severity estimates the potential consequence of a detection. Urgency helps decide what to work first by combining severity with evidence confidence and current operating context.

Confidence
How strongly the available evidence supports the detection.
Velocity
How quickly related activity is accumulating.
Privilege
Whether administrative identities or sensitive roles are involved.
Breadth
How many entities, accounts, or network segments are affected.
Blast radius
The plausible scope of impact if the activity succeeds.

Investigation playbook

How to evaluate a signal

Evidence before action
  1. Validate collection.Check source and sensor health, event time, region, account, and whether expected telemetry is missing.
  2. Read the detection claim.Identify the behavior being asserted and separate observed facts from inferred intent.
  3. Establish context.Review asset criticality, identity privilege, exposure, peer behavior, threat intelligence, and prior activity.
  4. Reconstruct the path.Use records and topology replay to determine origin, sequence, affected entities, and possible lateral movement.
  5. Decide and document.Close as expected behavior, tune the detection, escalate the case, or request a reversible response with approval.

Reference

Analyst glossary

VPC Flow Log

A metadata record describing a network flow, commonly including source, destination, ports, protocol, packet and byte counts, action, and time range.

Entity

A resolvable object involved in activity, such as an IP address, workload, host, user, role, account, or application.

Community ID

A direction-independent flow identifier used to correlate the same network session across compatible tools and sensors.

OCSF

The Open Cybersecurity Schema Framework. SignalPrism uses it to represent network activity and security findings consistently across integrations.

Baseline and drift

A baseline represents expected peer or seasonal behavior. Drift indicates that the underlying behavior has changed enough to require review or model retraining.

False positive

A detection that correctly matched its logic but does not represent unwanted activity in context. Document why, then tune narrowly without hiding similar threats.
